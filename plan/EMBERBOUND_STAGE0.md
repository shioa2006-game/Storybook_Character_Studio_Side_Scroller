# EMBERBOUND 段階0 表示試作の結果

作成日：2026年10月25日

[流用計画](EMBERBOUND_CHARACTER_REUSE_PLAN.md)の段階0 (量産の前に少数で表示を試す) の結果。ゲーム側の数値は[表示・コード調査](CHARACTER_RENDERING_AUDIT.md)による。確認ページは [tests/browser/emberbound-stage0.html](../tests/browser/emberbound-stage0.html) (サーバー経由で開く)。

## 1. 試したこと

- ゲームの戦闘画面と同じ 400×180・地面 y=150 に、味方4人と敵の位置を調査の座標どおりに置いた。
- 今の Studio のキャラクターを仮の役として、調査の描画高さ (tier 0・idle 先頭コマ) に縮めて描いた。衛士 → Guardian (30)、弓使い → Ranger (27)、魔法使い → Arcanist (28)、剣士 → Oracle の位置 (25)、ゴブリン → Ash Brute (24)、骸骨 → Frost Revenant (23)、暗黒魔法使い → Gloom Caster (21)、骸骨弓兵 → Drowned Archer (25)、スライム → 小型 (15)、王 → Ember Tyrant (38)、魔王 → Hollow Sovereign (70)。
- 縮小率は「ゲームの高さ ÷ Studio の高さ」。Studio の高さは idle 先頭コマの不透明画素 (アルファ 40 超。ゲームの `spriteBounds` と同じ基準) から自動で測る。Studio の高さは衛士 123、弓使い 103、魔法使い 133 で、縮小率はおよそ 0.19〜0.32。
- 次の組み合わせを比べた: 描き方 (高解像度の層に描く／400×180 の画像に描いて拡大)、表示の倍率 ×2〜×5 (ゲーム画面1ピクセル = 何デバイス画素か)、線の太さ (Studio のまま／自動)、攻撃の長さ (Studio のまま／0.6・0.4・0.2秒)、被弾の白い点滅。

## 2. 結果

| 項目 | 結果 |
|---|---|
| 400×180 に描いて拡大 | 体の高さが 25〜30 画素しかなく、鉛筆の線・点描・顔がにじんだ四角の塊になる。×3・×4 に拡大しても戻らない。**この方式は使えない。** |
| 高解像度の層 ×4 | 縮小率 × 4 ≒ 0.8〜1.3 で、**Studio の等倍とほぼ同じ見え方**。線・顔・装備がそのまま読める。 |
| 高解像度の層 ×3 | 細部 (点描・小さな留め具) は弱まるが、顔・装備・色・外形はよく読める。 |
| 高解像度の層 ×2 | 小さいが読める。線を「自動」で太くすると外形がはっきりする。 |
| 線の太さ「自動」 | `線の倍率 = max(1, 1 ÷ (縮小率 × 表示の倍率))`。Studio の等倍より細くならないように補う。×2 で約2倍、×4 ではほぼ1倍。 |
| 被弾の白い点滅 | 描いたコマを白で塗りつぶす (`source-atop`) だけで、ゲームと同じ白いシルエットになる。 |
| 描画の時間 | 10体を毎フレーム線から描くと、1フレーム約 14〜30 ms (今回の計測環境では値が粗い)。60fps (16 ms) に収まらないので、**ゲームでは作り置きのコマ (Cached Frames) を貼る**。 |

## 3. 決めること

### 3.1 描き方 (推奨: 高解像度の層)

キャラクターを 400×180 の画像ではなく、拡大後の画面と同じ画素数の別の層に描く。ゲームはすでに文字・アイコン用に同じ画素数の overlay canvas (`k = overlay の内部幅 ÷ 400`) を持っているので、その下にキャラクター用の層を1枚足す形になる。

ゲーム側で必要な作業 (Codex 側):

- キャラクター用の canvas を world と overlay の間に追加し、world と同じ位置・大きさで重ねる。
- 戦闘の `getUnitSprite` の代わりに、(キャラクター・動作・コマ・tier・k) ごとの作り置きのコマを足元の位置へ貼る。
- 今 world に描いている、キャラクターの手前に出るべき演出 (矢・火花・凍結の氷・Mark の角など) の重ね順を見直す。キャラクターの層より下に描くと隠れる。
- 野営地・パーティ画面・加入通知・タイトルも、同じ作り置きのコマを使うよう個別につなぐ。

### 3.2 大きさ

- 体の高さは調査の描画高さに合わせる (味方 25〜30、小型 10〜17、中型 17〜25、大型 36、エリート 29〜44、巨大ボス 62〜70)。縮小率は確認ページと同じ方法で自動で求める。
- 影の4人は味方の 1.5倍。
- 足元はゲームの足元アンカーに合わせる。HP バー・溜めゲージは今の基準 (idle 先頭コマの上端) のまま使える。

### 3.3 描き込みの量

表示の倍率は画面の大きさで変わる (フルHDで全幅近くなら約 ×4、小さな画面では ×2〜×3。スマートフォンは DPR が大きいので ×4 以上になりやすい)。**×3 で読めることを基準に描く**: 2.2頭身の大きな頭、太い外形線、はっきりした色分けを優先し、点描や小さな留め具は ×4 以上で見える「おまけ」とする。

### 3.4 攻撃の長さ (未決定)

ゲームの攻撃ポーズは 0.2秒、命中は開始から 0.12〜0.3秒後。Studio の攻撃は 1.1〜1.8秒で、振りかぶり (溜め) が長い。0.2秒に縮めると、衛士の振りかぶりは約 0.09秒 (60fps で5コマほど) しかなく、動きとして読みにくい見込み (確認ページの「攻撃の長さ」で実際に再生して判断する。今回の確認環境ではアニメーションを滑らかに再生できず、静止コマでしか見ていない)。案は次の3つ。

| 案 | 内容 | 手間 |
|---|---|---|
| A 早回し | 今の攻撃をゲームの長さ (0.2〜0.4秒) に縮めて再生する | 最小。ただし動きは読みにくい |
| B 短い攻撃を作る | ゲーム用に「構え → 打ち込み → 戻り」の短い攻撃 (約0.3秒、命中 0.12秒前後) を各キャラクターに足す | 中。読みやすさと命中のタイミングが合う |
| C 振りかぶりを前倒し | 次の攻撃までの時間 (ゲームの `atkTimer`) を見て、命中の前から振りかぶりを始める | ゲーム側の改造が大きい。攻撃速度の変化にも追従が必要 |

推奨は B。待機を「構え」に近づけておくと、短い攻撃でも動きが読める。詠唱 (0.2秒)・被弾 (0.14秒、スタン・凍結はこの絵で止める)・戦闘不能 (1コマで保持) も、同じく短い専用の動作として作る。

## 4. 次に進む前に

1. 3.1 の描き方をゲーム側 (Codex) で受け入れられるか確認する。
2. 3.4 の攻撃の長さを決める。
3. 決まったら、Guardian・Ranger・Arcanist の RPG 用の派生 (`characters/eb-guardian/` など) で、短い動作と被弾・戦闘不能を1体試作してから量産に入る。

## 5. 決定事項 (2026年10月25日)

| 項目 | 決定 |
|---|---|
| 描き方 | 3.1 のとおり高解像度の層に描く。ただしゲームへの組み込みでは、毎フレーム線から描かず、**このリポジトリのプログラムで描いたキャラクターから必要なコマを画像として切り出して使う** (切り出しはゲームへの移植のときに行う)。このリポジトリではキャラクターをプログラムとして実装する。 |
| 大きさ | 3.2 のとおり、ゲームの描画高さに合わせる。 |
| 描き込みの量 | 3.3 のとおり、×3 で読めることを基準にする。 |
| 攻撃の長さ | 3.4 の案B。ゲーム用の短い攻撃 (約0.3秒、命中 0.12秒前後) を作る。 |
| 作る動作 | 味方は待機・歩行・攻撃・詠唱 (スキル)・被弾・戦闘不能。魔法・溜め攻撃を持つ敵は待機・攻撃・詠唱 (溜め)・被弾。その他の敵は待機・攻撃・被弾。 |
| 作る順番 | 任せる ([制作ルール](EMBERBOUND_PRODUCTION.md)の順番)。 |
| 背景 | ゲームを作るときに、Studio の横スクロールのような線画の背景に変える。 |
| 進め方 | このリポジトリで必要なキャラクターをすべて作る → ゲームのリポジトリへこのリポジトリをコピーする → Codex で移植する。 |
