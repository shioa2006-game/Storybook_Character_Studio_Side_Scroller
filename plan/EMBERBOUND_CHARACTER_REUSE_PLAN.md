# EMBERBOUND EXPEDITION キャラクター流用計画

作成日：2026年10月25日

制作元は `Storybook_Character_Studio_Side_Scroller`、組み込み先は `incremental_rpg_opus`。既存の手描きキャラクター11種を活用して、[RPGのキャラクター一覧](../../incremental_rpg_opus/docs/CHARACTER_CATALOG.md)の44種を制作する。

**推奨は、味方3種の基本造形を流用し、人型を中心に18種を改造、19種を新たに造形し、最後に味方4種から影4種を派生させる方針。** 既存11種のうち10種を主な制作元に使う。スライムは、敵の種族・シルエットも変更する場合の代替候補とする。

機能・加入順・敵編成・能力は元ゲームを基準とし、外見はStudioの絵本風に合わせる。既存キャラクターに適した特徴は残す前提なので、例えばRangerは金髪のエルフ、Arcanistは顔の見える白髪の魔法使いとして再解釈する。元のピクセル絵の完全な再現を目標にはしない。

本書は制作計画。流用先のキャラクター追加、既存モデルの変更、ゲームへの組み込みは未実施。

## 流用の分類と作業量の捉え方

| 分類 | 対象数 | 判断基準 |
|---|---:|---|
| A 基本造形を流用 | 3 | 既存の体型・衣装・武器・基本3動作を主に採用。専用スキル動作や装備差分は別途必要。 |
| B 既存モデルを改造 | 18 | 人体・衣装構造・武器の保持・動作の一部を流用し、頭部・装備・体格などを変更する。 |
| C 新しい造形を制作 | 19 | 適切な完成モデルがなく、固有のシルエットと動きを作る。共通の線・塗り・登録・キャッシュは流用できる。 |
| D 完成モデルから派生 | 4 | RPG用の味方4種が完成した後、同じ形状と動作から影を作る。 |
| **合計** | **44** | 装備段階・動作コマは種類数に含めない。 |

Bの「小・中・大」は同じ分類内での改造規模の目安。B大は色替え程度の作業ではなく、新しい頭部や装備、動作を相当量作る。種類数をそのまま工数の削減率としては扱わない。

## 既存11種の評価

全11種が右向きR・左向きLの待機 `idle`、歩行 `walk`、攻撃 `attack` に対応する。魔法使い2種は、`attack` の中で杖と魔法書を使った詠唱を行う。登録済みモデルに独立した `cast`、`hurt`、`dead` はない。

| 既存キャラクターとID | 現在の外見・装備 | 主な流用先 | 採用方針 |
|---|---|---|---|
| **灰燼の衛士** `warrior` | 銀の重装鎧、赤茶の羽飾り、大盾。左手に剣、右手に盾。 | Guardian、Coral Knight、Hollow Knight、Glacial Warden | 最も重要な重装モデル。Guardianは造形をほぼ採用し、他の騎士は派生として作る。 |
| **金髪エルフの弓使い** `archer` | 金髪、尖った耳、緑のフードとマント。左手に弓、右手で弦を引き、背に矢筒。 | Ranger、Rime Archer | Rangerの基本モデルとして採用。寒冷地版は耳・髪・フード・配色を調整する。 |
| **魔法使い** `mage` | 白髪、青灰色の尖り帽子、長衣。左手に水晶杖、右手に魔導書。 | Arcanist、Oracle、Rimequeen Isveil | Arcanistの基本モデル。Oracleと氷の女王には姿勢・衣装構造を使い、頭部・杖・服を作り直す。 |
| **緑フードの若き剣士** `swordsman` | 茶髪、オリーブ色のフード、生成りの服。右手に剣、左腕に木の丸盾。 | Ashen Echo | 灰色化と透過表現を加え、過去の冒険者の残響にする。 |
| **骸骨の番兵** `skeleton` | 大きな象牙色の頭蓋骨、骨の胴体。右手に傷んだ剣、左腕に木盾。 | Frost Revenant | 骨格と斬撃を利用し、氷の兜・鎧・マントで凍てついた騎士にする。 |
| **骸骨弓兵** `skeleton-archer` | 象牙色の骨、茶の革装備。木弓と矢筒。 | Drowned Archer | 骨と弓の仕組みを採用し、青緑のぼろ布や水没した質感を加える。 |
| **暗黒魔法使い** `dark-mage` | 深紫のフード、暗い顔と琥珀色の目。紫水晶の杖と髑髏印の魔法書。 | Gloom Caster、Geomancer、Ember Acolyte、Ice Wraith | 敵術師の共通の土台。衣装色だけでなく、杖・本・頭飾り・裾で役割を区別する。 |
| **ゴブリン** `goblin` | 緑の肌、大耳、牙、前傾姿勢と革装備。左手に鋲付き棍棒。 | Ash Brute、Tideling | 棍棒攻撃や小型人型の動きを流用。Ash Bruteは体格拡大、Tidelingは魚の頭とひれを新造する。 |
| **王** `king` | 金冠、銀の鎧、赤いマント。右手に剣、左手は空き。 | Ember Tyrant | 冠・鎧・マント・斬撃を活用し、顔の隠れた炎の暴君に変更する。 |
| **魔王** `demon-king` | 鉄冠、黒い兜と鎧、赤い目、マント。右手に大剣。 | Abyssal Herald、The Hollow Sovereign | 威圧感のある頭部・鎧・マントを活用。杖・角・眼状の顔・詠唱は別途制作する。 |
| **スライム** `slime` | 淡い青色の柔らかな体。伸縮、跳躍、体当たり。 | 任意案としてVoidspawn | 現行の獣型を維持する標準案では未採用。虚無の粘体へ外見を変更する場合に有効。 |

衛士だけは、剣士や王と剣・盾の持ち手が異なる。流用先で左右を統一する必要はなく、原型の持ち手を維持すると修正を減らせる。敵向きの表示にはLを使い、単純な画像反転で持ち手を入れ替えない。

### スライムを使う代替案

外見の変更幅を広げるなら、Voidspawnを「虚無の粘体」として制作する。`slime`の丸い体・伸縮・体当たりを残し、濃紫の体、複数の緑の目、大きな口、橙や緑の亀裂に変える。

ゲームID `voidspawn`、前衛への近接攻撃、召喚される機能、他の敵との連携は維持できる。この場合はVoidspawnをCからBへ変更し、**A 3・B 19・C 18・D 4**となり、既存11種すべてを流用元にできる。元の多脚の獣という見た目からは離れるため、標準案とは分けて判断する。

## 新規19種も系統ごとに作る

新規キャラクターを1種ずつ独立実装すると、歩行や素材表現を重複して作ることになる。次の順序で共通部分を育てる。

| 系統 | 最初に作るもの | 次に展開するもの | 共通にできる部分 |
|---|---|---|---|
| 甲虫・結晶虫 | Ash Crawler | Crystal Mite | 脚の配置、這う動き、低い胴の接地 |
| 火球 | Ember Wisp | 炎系キャラクターの発光部 | 炎の輪郭、揺れ、光。体全体の形状は個別。 |
| 四足獣 | Charwolf | Frost Hound、Thornback Boar、Shardback | 歩行周期、四足の接地、突進。体格と顔は個別。 |
| 異形獣 | Voidspawn | 他の影系キャラクターの素材表現 | 影の表面、目の発光。脚の構造は専用。 |
| 樹木 | Cinder Sapling | Gnarlwood | 樹皮、枝、根、燃える裂け目 |
| 蟹 | Reef Lurker | 必要なら他の甲殻系 | 脚と鋏の動き。甲虫とは別の体型。 |
| 人魚・蛇体 | Siren | Coilscale Matriarch | 上半身、髪、鱗、尾の揺れの補間。魚尾と蛇体は別造形。 |
| 有翼生物 | Gem Bat | Lantern Eater、Cinder Phoenix | 羽ばたきの位相と浮遊。膜・虫の羽・羽毛は個別。 |
| 結晶構造物 | Prism Sentinel | 結晶系の装飾 | 結晶の面、核、充填時の発光 |
| ゴーレム | Geode Colossus | Flame Construct | 太い関節、重い歩行、拳の打撃。岩石と金属は個別。 |

人間型はStudioの約2.2頭身を継承する。四足獣、蟹、鳥、巨大樹などに人間型の頭身や骨格を無理に適用しない。

## 造形とは別に必要な共通対応

### 動作とゲームの時間をつなぐ

| 元ゲームが必要とする表示 | Studioの現状 | 計画 |
|---|---|---|
| 待機・歩行・通常攻撃 | 11種すべてに実装済み | 主に流用し、ゲームの速度・向き・足元座標に合わせる。 |
| 詠唱とスキル | 魔法使いは`attack`内で詠唱。独立`cast`は未定義 | RPG用の定義へ`cast`を追加。盾打ち・上向き射撃・Meteor・Sanctuaryなどは専用の姿勢を用意する。 |
| 被弾・スタン・凍結 | 専用`hurt`は未定義 | 小さな反動姿勢を作り、停止・白い点滅・氷などはRPG側の状態表示と組み合わせる。 |
| 戦闘不能 | 専用`dead`は未定義 | 人型・獣・飛行・樹木など系統ごとに倒れ方を用意する。死亡の確定は元ゲームの戦闘処理に従う。 |
| 溜め攻撃・段階移行・復活 | 専用のゲーム状態なし | ゲームから状態と進行度を渡す。溜め・攻撃・復帰を分けて再生できるようにする。 |

定義の `actions` とキャッシュは追加の動作名を扱えるが、既存の描画関数がその動作を描くよう実装する必要がある。定義にない動作は待機へフォールバックする。Studioのボタンは定義した動作を列挙する一方、横スクロールの操作サンプルは基本3動作が中心なので、追加動作の確認はStudio詳細・シートでも行う。

既存の攻撃アニメーションはおおむね1.1〜1.8秒で、RPG側の通常の攻撃表示は約0.2秒を基準にしている。さらに敵味方の攻撃速度は成長や状態異常で変わる。**Studioの攻撃が終わるまで戦闘を待たせず、RPGの攻撃イベント・着弾時刻に合わせて動作の位相を調整する。** 特に弓は、手元の矢が消える瞬間とゲーム側の飛翔体を合わせる。

`once`の指定だけに頼らず、単発動作を最後の姿勢で止める・待機へ戻す処理を組み込み側で持つ。現在のキャッシュの時刻計算は周期で折り返すため、死亡姿勢の再ループや溜め動作の早すぎる解放を避ける。

### 装備6段階と影の色替え

Studioには現在、RPGの装備段階に対応する共通パレット切替APIや装備選択UIはない。各キャラクターの色は主にファイル内の定数であり、名前やメタデータの変更だけでは色を変えられない。

1. RPG用の派生モデルで、金属・布・革・武器・発光の色と装飾を設定化する。
2. 味方1種につき6段階を同じ形状・動作から生成する。色だけでなく、高段階の装飾や光で成長を示す。
3. 影は味方の完成形を使い、専用配色・目・亀裂を加える。別の人物として描き直さない。
4. キャッシュには段階と影の区別を含める。同じIDの定義を毎フレーム変更する方法は避け、例えば`eb-guardian-t0`〜`eb-guardian-t5`のような安定した描画IDを使う。
5. Studioで段階を比較できる小さな表示機能を追加する。現状のUIで装備段階を切り替えられるとは扱わない。

完成時の外見は、味方4種×6段階と敵40種で64パターンになる。ただし造形や動作を64組独立して制作する必要はない。影には6段階を重複して作らず、専用の1外見ずつを用意する。

### 原本とゲームIDを分けて管理する

既存11種は制作見本として残し、RPG向けモデルは `characters/eb-guardian/character.js` など別の定義として追加する。StudioのIDは英小文字・数字・ハイフンで、元ゲームの `ash_crawler` のようなアンダースコアは使えないため、`ash_crawler → eb-ash-crawler` のような対応を組み込み側に置く。

共通部品は `characters/shared/emberbound/` に置く案を採用する。共有化するのはRPG向けの派生コードであり、既存モデルの色定数を全体で書き換える方法は取らない。人体・接地・塗りは `src/authoring.js` を利用する。

現在の出力ツールは、選択されていない追加キャラクターへの直接依存を拒否する。例えば新しいGuardianが元の `characters/warrior/character.js` をそのままimportすると、Guardianだけを出力した際に問題になる。必要な造形・動作をRPG用共有部品へ移すか、独立した派生実装を作り、元の完成モデルは保持する。

## ゲームへ接続する際の方針

キャラクターの原本はStudio、HP・ダメージ・加入・召喚・セーブなどの原本はRPG側とする。Studioの `scroll/game.js` は歩行・攻撃の確認用であり、RPGの戦闘処理として移植しない。

| 接続点 | 必要な対応 |
|---|---|
| 描画API | RPG側の`getUnitSprite`、`frameCount`、白い被弾シルエットなどに対応する描画用アダプターを作る。キャラクター定義から必要なコマを描き、元ゲームが扱う画像・基準位置へ変換する。 |
| 解像度 | RPGは400×180のピクセル描画、Studioは細線を含む手描き。まず実際の戦闘サイズで判読性を比較し、手描き線を保つ表示用バッファの解像度を決める。論理座標と戦闘ルールは維持する。 |
| 大きさと足元 | `frameBox`の余白を体の大きさと見なさず、描かれた体と足元基準でサイズを合わせる。通常・エリート・ボスの差、HPバー、クリック対象の位置を確認する。 |
| 向き | 味方は主にR、敵はL。Studioの左右投影を使い、持ち手を保つ。 |
| エフェクト | Mark、Burn、Doom、Barrier、敵シールド、溜めゲージなどは元ゲームの状態から表示する。手描きの体に重ねたときの見やすさを調整する。 |
| 戦闘以外の画面 | パーティ画面・加入通知・野営地・タイトルも同じキャラクターを使う。戦闘用APIの差し替えだけでは、元のピクセル絵が残る経路があるため個別に接続する。 |
| キャッシュ | 全44種・全装備を最初に一括生成せず、使用するパーティとエリアを中心に準備する。段階変更やエリア移動時の解放を決める。生成時間とメモリを実測する。 |
| 持ち出し | `tools/export-game.mjs`のコード出力を利用する。PNGシート出力ツールではない。出力後のゲーム用コピーを制作原本にはしない。 |
| 配布 | 元ゲームのVite単一HTMLビルドに取り込み、オフライン起動を確認する。StudioのES Moduleサンプルをそのまま`file://`で開く方法とは別に検証する。 |

## 推奨する制作順

| 段階 | 制作・確認する範囲 | 終了条件 |
|---|---|---|
| **0 少数で接続を試す** | 衛士・弓使い・魔法使いを使い、RPGの戦闘サイズ・足元・攻撃タイミング・通常表示の線を確認する。1体で装備差分と被弾・死亡表示も試す。 | 表示倍率と解像度、アニメーションの接続方法、キャッシュ方針が決まる。44種の量産に入る前に行う。 |
| **1 味方と基本部品** | Guardian、Ranger、Arcanistを派生化し、Oracleを制作。専用スキル、装備6段階、被弾・戦闘不能をそろえる。その後、影4種の配色とサイズを試す。 | 4職の役割が見た目で区別でき、成長と影への派生が成立する。 |
| **2 第1エリアを完成させる** | Ash Bruteを改造し、甲虫・火球・四足獣・苗木を制作。猪とGnarlwoodへ展開する。 | 通常戦・エリート・召喚・ボス・加入まで、最初のエリアを新しい画風で確認できる。 |
| **3 人型の派生をまとめる** | 骸骨弓兵、術師、騎士、王・魔王を元に、第2〜第6エリアのB分類を制作。回復役・シールド役・大技の敵を外見で区別する。 | 各派生の武器・顔・装飾・詠唱が固有化され、左右と基本動作が通る。 |
| **4 非人型を系統別に増やす** | 甲虫・四足の派生、結晶構造物、ゴーレム、有翼生物、蟹、人魚・蛇の順に制作。 | C分類19種がそろい、潜航・復活・爆発・召喚でも識別できる。 |
| **5 最終戦と全体を仕上げる** | 影4種を味方の最終版に追従させ、44種の対応、全エリア、戦闘外画面、エクスポートを確認。 | 既存機能を維持した状態で、全キャラクターを新しい描画で使用できる。 |

直近の制作対象は **Guardian、Ranger、Arcanistの表示試作 → Oracle → 第1エリア** とする。人型を大量に作る前にOracleを確定すると、回復職と氷の女王の共通部品にも早く着手できる。

## 制作時の確認項目

- Studioで左右・全対応動作を、拡大表示と実際のゲームサイズの両方で確認する。LiveとCachedで装備・矢・発光が一致することを確かめる。
- 武器の保持、頭や胴を通り抜けない軌道、床へのめり込み、`frameBox`からのはみ出しを確認する。武器変更後のモデルには、その体格に合う検査を用意する。
- 未変更の既存11種の描画が変わっていないことを確認する。新規・変更した絵だけを意図した差分として扱う。
- 元ゲームで攻撃回数、ダメージ、召喚数、状態異常、加入、転生、セーブの挙動が変わっていないことを確認する。アニメーションを理由に戦闘を遅延させない。
- 群れの複数表示と影4体の同時戦闘で、識別性・表示速度・キャッシュ容量を確認する。
- コードを出力し、Studioから独立した場所で読めることと、RPGの配布ビルドに取り込めることを確認する。

今回確認した範囲は、現行カタログ11種、動作・色・装備の定義、共有化と出力の制約、ブラウザー上の左右の待機・攻撃の代表姿勢。派生モデルの品質、全位相の描画、RPGへの組み込み後の画質・性能は、制作工程で確認する。
