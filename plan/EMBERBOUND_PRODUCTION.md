# EMBERBOUND キャラクター制作ルール

作成日：2026年10月25日

[キャラクター一覧](CHARACTER_CATALOG.md)の44種を、このリポジトリでプログラムとして作るときのルールと進み具合。方針は[流用計画](EMBERBOUND_CHARACTER_REUSE_PLAN.md)、表示の基準は[段階0の結果](EMBERBOUND_STAGE0.md)、ゲーム側の数値は[表示・コード調査](CHARACTER_RENDERING_AUDIT.md)による。

## 1. 置き場所と名前

- 1体 = `characters/eb-<名前>/character.js`。Studio の ID は `eb-` + ゲームの ID のアンダースコアをハイフンにしたもの (`ash_crawler` → `eb-ash-crawler`)。
- 定義に `emberbound: { gameId, heightPx, facing }` を書く (ゲームの ID・ゲームでの描画高さ・ゲームでの向き)。移植のときの対応表になる。
- 既存の11体は見本として変えない。流用するときはファイルを**コピー**して直す (別のキャラクターを import すると、書き出しで単独に取り出せない)。複数の EMBERBOUND キャラクターで共有する部品は `characters/shared/emberbound/` に置く。
- **新しいキャラクターは `npm run eb:new` で始める**。元にするキャラクターのファイルをコピーして名前を付け替え、`emberbound` と Studio の情報を書き、カタログに登録し、元に武器の検査 (`ARMED`) があれば同じ読み方で1行足す。例:
  `npm run eb:new -- --game oracle --from eb-arcanist --name "Oracle（暁の巫女）" --height 25 --description "…"`
  (`--from` は `characters/` のフォルダ名。`--facing L` で敵向き、`--category` でカテゴリー)
- 共通部品 [characters/shared/emberbound/actions.js](../characters/shared/emberbound/actions.js): ゲームの長さ (`GAME_T`)、被弾・戦闘不能の動作の定義 (`hurtAction` / `deadAction`)、反動の量 (`hurtAmount`)、体ごとの傾きと倒れ方 (`fallTilt` / `withTilt`)。各キャラクターは見た目と攻撃・詠唱の動きだけを書く。
- 共通部品 [characters/shared/emberbound/creature.js](../characters/shared/emberbound/creature.js): 人型のリグを使わず手で描く体 (四足獣・虫・炎・樹木・結晶・岩の巨人など) の部品。右向きの座標で描き、`face(direction)` で左右を写す。脚 (`leg`)、先細りの肢 (`limb`)、毛の縁 (`tufted`)、炎 (`flame`)、結晶 (`crystal`)、岩の板 (`rock`)、樹皮 (`bark`・`TREE`)、描画と傾き (`drawCreature`)。
- 共通部品 [characters/shared/emberbound/merfolk.js](../characters/shared/emberbound/merfolk.js): 尾や蛇体のある体 (Siren・Coilscale) の部品。鱗の筒 (`tube`。切り口に線を引かない `openEnds`)、ひれ (`fanFin`)、細い腕と手 (`arm`)、大きな目 (`eyes`)。
- Studio のカテゴリーは `EMBERBOUND 味方` / `EMBERBOUND 第1エリア` … / `EMBERBOUND 影` とする。ギャラリーの並びは `studio.order` の番号 (味方4人が1〜4、以降はエリア順・一覧の掲載順。元からある11体は番号なしで最後)。新しいキャラクターには必ず付ける。

## 2. 動作と長さ

ゲームの動作名をそのまま使う。左右 (R / L) は両方作る (ゲームでは味方が R、敵が L)。

| 対象 | 作る動作 |
|---|---|
| 味方4人 | `idle`・`walk`・`attack`・`cast` (スキル)・`hurt`・`dead` |
| 魔法・溜め攻撃を持つ敵 | `idle`・`attack`・`cast` (溜め・詠唱)・`hurt` |
| その他の敵 | `idle`・`attack`・`hurt` |

| 動作 | 長さ・作り方 (ゲームの使い方) |
|---|---|
| `idle` | ループ。ゲームは 1/2.6 秒ごとにコマを替える。呼吸程度の小さな動き |
| `walk` | ループ。味方だけが使う (敵は歩かない) |
| `attack` | **約0.3秒、once**。ゲームの攻撃ポーズは 0.2秒、命中は近接 0.12〜0.15秒後。**命中を u ≒ 0.4 (0.12秒) に置く**。魔法の弾はゲームが攻撃の開始と同時に出すので、**放つ瞬間を最初の 0.03〜0.05秒に置く**。**弓は例外**: 矢をつがえて引き絞る動きを見せるため、**放つ瞬間を u = 0.5 (0.15秒) に置く** (Ranger・Drowned Archer・Rime Archer)。移植のときは、ゲーム側で矢を出す時刻を定義の `releaseAt` に合わせる |
| `cast` | 味方のスキル・魔法 (0.2秒) は once。**敵の溜めはゲームが 1/6 秒ごとにループで再生する**ので、敵の `cast` は始めと終わりがつながるループにする |
| `hurt` | 約0.3秒、once。ゲームは 0.14秒しか見せないので、**最初の 0.05秒で反動の頂点**に達する。スタン・凍結はこの最初の絵で止まる |
| `dead` | 味方だけ。once、最後の絵を保つ (`hold: true`)。敵の退場はゲームが最後の絵から作るので不要 |

被弾の白い点滅はキャラクター側では描かない (ゲームが同じ絵を白く塗りつぶす)。

## 3. 大きさと描き込み

- ゲームでの描画高さ (`heightPx`) は[表示・コード調査](CHARACTER_RENDERING_AUDIT.md)の表の値。Studio の中では好きな大きさで描き、縮小率はゲーム側で「ゲームの高さ ÷ Studio の高さ」(idle 先頭コマの不透明画素の高さ) から決める。
- **×3 で読めること**を基準にする: 太い外形線、はっきりした色分け、リグの人間型は大きな頭 (約2.2頭身)。手描きの大柄な体やボスは参考画像の体格に合わせ、頭を小さく体を大きくする (6.2)。点描・小さな留め具は ×4 以上で見える「おまけ」。
- 四足獣・蟹・鳥・樹木などに人間型の頭身や骨格を当てはめない。

## 4. 確認

1体ごとに次の2つで確かめてから報告する。

1. **`npm run eb:check`**: カタログの更新、EMBERBOUND のキャラクターの絵の指紋の更新、全テスト (武器が体を通り抜けないこと・床に潜らないこと、手描きの人型の骨組み (Glacial Warden) を含む) を1回で行う。**EMBERBOUND 以外のキャラクターの絵が変わっていたら止まる**。最後に、変わったキャラクターの確認ページを表示する。
2. **[eb-review.html](../tests/browser/eb-review.html)`?id=eb-…`** (サーバー経由): 1画面に、全動作 × 左右の要所 (始め・溜め・命中や放つ瞬間・振り抜き)、ゲームの戦闘サイズ (×3) の要所、描画範囲 (`frameBox`) のはみ出しの有無をまとめて表示する。`&act=cast` でその動作だけを8コマ大きく、`&k=4` でゲームのサイズの倍率、`&scale=1.6` で上段の拡大。

確認ページでは、見えるかどうかだけでなく次を見る (6章の内容の要約):

- [ ] 前側の腕・脚は奥、後ろ側は手前になっている (6.1)
- [ ] 片手で持つ武器は左右で同じ手 (持ち替えて見えない)。両手持ちは左右同じ絵で、奥のこぶしが手前のこぶしの先 (6.1)
- [ ] 手が肩から届いて腕から外れない。肘が手の高さに合った向きに曲がり、前へ折れていない (6.2)
- [ ] 部品のあいだに背景のすき間がない。動いている途中も外れない (6.3)
- [ ] 顔に髪・武器・光・襟・手前の腕が重なっていない。手前の手の武器は顔より手前 (6.4)
- [ ] 左右対の部品が同じ形・色、体の中心の飾りが真ん中にある (6.4)
- [ ] 武器が体を突き抜けない、物理的にありえる動き (自動検査と目視)
- [ ] 動きの参考画像があればそのとおり。弓は引き絞ってから放つ、魔法は杖を振って唱える (6.6)
- [ ] ゲームの大きさ (×3) で何をしているか読める

武器を持つキャラクターは、武器の読み方が元と違えば `tests/node/lib/clearance.mjs` の `ARMED` を直す。戦闘の並びの中で見たいときは [emberbound-stage0.html](../tests/browser/emberbound-stage0.html)。

## 6. レビューで分かったこと (ノウハウ)

第1〜第4エリアの29体を作り、ユーザーの確認で直した点から、次のキャラクターでも最初から守るべきことをまとめる。右向きで考えるときは「前 = 顔の向き」、左向き (敵のゲームでの向き) では前が画面の左になる。体の作り方は2通りある: 人型のリグ (`rigFrame`。左右の手を投影で描く) と、右向きの座標で手描きして左右を写す体 (`creature.js` / `merfolk.js`)。手描きの体は、リグなら自動で決まること (奥・手前、持ち手、肘) を自分で決める必要がある。

### 6.1 手足の奥・手前と持ち手

- **前側 (顔の向き) の腕・脚は奥、後ろ側は手前**。横から見た体では、前側の腕は胴の向こうに回る。左向きの絵なら、画面の左の手が胴の奥、右の手が胴の手前になる。手描きの体では部品の描画順 (`d`) をこの規則に合わせる (苗木・Siren で逆にしていて指摘された)。
- 手前の腕が胸の前を横切るのはよい (Siren の後ろ側の手を胸に添える)。前側の腕は、肩が胴の陰から出て前へ伸びる形にする。
- **片手で持つ武器・杖は、左右どちらの向きでも同じ手で持つ**。リグは自動でそうなる。手描きの体は絵を写すだけだと持ち替えて見える (左向きで手前の左手に持つ杖が、右向きでは手前の右手に移る。Rimequeen・Coilscale で指摘された)。向きごとの手の位置 (`HANDS`) を持ち、右向きでは持つ側の腕を奥 (`d` を体より小さく) にして武器を体の前に持たせ、空いた手を手前にする。
- **両手で持つ武器は例外で、左右とも同じ絵を写す**。手前の手のこぶしで柄の端を、奥の手のこぶしでその少し先 (武器の頭の側) を握らせ、奥の腕は体の向こうに隠す (Glacial Warden。ユーザーの指示)。右向きだけ奥・手前を入れ替えると、奥の手が柄の端に回り、奥の腕の肘が体の前に出ておかしく見えた。
- リグのキャラクターで持ち手を変えるときは、**姿勢をまるごと鏡に写す**。弓を右手に持ち替えた Drowned Archer は、手・肘・弓・体の横方向 (b) の符号、構えのひねり (`yaw`)、前に出す足、弓の傾き、矢の発射位置まで反転した (`drownedPose` の `nb`)。手だけ入れ替えると構えが崩れる。

### 6.2 手描きの人型の骨組みと体格

- **参考画像の体格がリグ (大きな頭のちび体型) と違うときは、リグを流用せず手描きにする**。Glacial Warden は Guardian の体を流用して頭が大きく体が小さくなり、作り直した。**ボスは特に、頭を小さく体を大きく** (Rimequeen はリグの体で頭でっかちになり、Coilscale は人の上半身がとぐろに比べて小さかった)。
- **手描きの人型は骨組みから作る**。武器の位置だけを決めて腕を後から合わせると、手が肩から届かない位置に行き、腕が手から外れて体とちぐはぐになる (作り直し前の Glacial Warden)。肩・股・膝・足首を固定点にし、上腕と前腕の長さを決め、手の位置から肘を求める。
- **肘は2通りの解から、手の高さに合うほうを選ぶ** (`elbow`)。手が肩より低いときは下・後ろ。頭上に上げたときは両腕で頭を囲む形 (前側の腕の肘は前、後ろ側の腕の肘は後ろ)。曲げる向きを1つの符号で固定すると、手の位置によって肘が前へ折れる (Rimequeen の杖の腕、Glacial Warden の右向き)。
- **両手持ちは、両手を並べて (こぶし1つ分の間隔で) 柄の端寄りを握り、一緒に動かす**。手の位置は「両手の中点 ± 柄の向き × 間隔の半分」で決め、両手が同じ柄の上に乗るようにする。両手を離して別々の点として動かすと、腕がばらばらに見える (Glacial Warden)。
- **骨組みは数値のテストで全コマ確かめる** (`tests/node/eb-warden-skeleton.test.mjs`): 手が肩から届く、骨の長さが変わらない、手が肩より低いとき肘が前へ折れていない、顔 (兜の目の部分) に武器や手前の手が重ならない、武器が床に沈まない。肘の向きの取り違えのような誤りは、見た目より先にテストで見つかる。

### 6.3 部品のつながり

- **隣り合う部品のあいだに背景が見えてはいけない**。指摘されたすき間: 噛みつきで頭だけ前に出て首が外れる (焦げ狼)、甲羅のふちと体のあいだ (Reef Lurker)、触角の根元 (Crystal Mite)、あごと肩 (Coilscale)。
- 直し方の決まり:
  - 覆われる側の部品を、覆う側の下まで伸ばす (蟹の体の上の端を甲羅の内側まで)。
  - 生える部品は、親の部品の内側から始める (触角の根元を頭の中に置き、頭を後から描く)。
  - 動く部品のあいだには、両方の動きに追従するつなぎ (首) を置く。頭を拡大して描くときは、拡大後の位置でつなぐ。
- **蛇体・尾のような長い体は1本につながって見えること**。重なりの順を守るために何本かに分けて描くときは、切り口に輪郭線を引かない (`merfolk.js` の `tube` の `openEnds`)。切り口は、手前を通る部品の下に隠れる位置に置く。曲がりがきついと筒の内側が折れて線が出るので、点を足してゆるく曲げる。
- 地面に接する部品は y = 0 より下に沈めない (Coilscale のとぐろが床の下に出ていた)。浮く敵だけ例外。

### 6.4 顔と目立つ部品

- **顔の真ん中に物を重ねない**。垂れた髪 (Siren) は顔の後ろ・耳の下へ、槍 (Tideling)・三叉槍の振りかぶり (Coral Knight)・杖の光 (Geomancer)・杖の振り上げ (Rimequeen) は顔の前を横切らない高さと向きにした。
- ただし、**手前の手で持つ武器は顔より手前に描く** (Coilscale の三叉槍)。頭の後ろに隠すのはおかしい。顔の前を通るのが避けられないときは、向きや高さを変えて顔の外を通す。
- **襟・毛皮・肩当ては頭より奥に描く**。頭より手前に描くと、顔が毛皮に埋もれる (Glacial Warden)。腕を頭より高く上げるコマでは、その腕を頭の奥に回す。
- **体の中心にある飾りは体の真ん中に置く** (Geode Colossus の胸の晶洞が腕の付け根にあった)。横向きでも、胴の幅の中央に見える位置にする。
- **左右対の部品は形と色をそろえる** (Geode Colossus の両拳)。奥側を暗くしたいときも、形は同じにする。
- **何だか分からない形は消す**。Drowned Archer の胸の布は「板」にしか見えなかったので外した。参考画像にあっても、ゲームの大きさで読めない部品は省く。

### 6.5 形の作り方

- **リグの体では、横向きで潰れる形に注意する**。体の横方向 (b) だけに広がる形 (肩まわりの毛皮の襟) は、横向きでは奥行きになってほとんど見えない。前後 (a) と横 (b) の両方に広がる輪にする。
- **参考画像が正面向きで、真横では読めない生き物は、正面寄りで描く**。Gem Bat は真横だと翼が重なって蝙蝠に見えなかったので、翼を左右に大きく広げた正面寄りの姿にした。
- **布の裂けた裾・毛皮の縁は、小さな部品を並べず、一続きの輪郭にする**。毛皮の縁取りを丸い部品の連なりで描くと玉のつながりに見えた (Rime Archer)。裾の裂け目を別の帯で描くと脚に見えた (Ice Wraith)。裂け目や毛のふわふわは、衣の輪郭そのものの凸凹として描く。
- 結晶・岩は `creature.js` の `crystal` / `rock` を使う。結晶は小さいと棒に見えるので、幅を長さの4〜5割にする。
- 大きな頭のちびキャラの体を作るときは、頭と首がつながっているか、頭が肩に隠れていないかを最初に見る (Geode Colossus の頭が肩に埋もれていた)。

### 6.6 攻撃の見せ方

- **動きの参考画像があれば、そのコマを1つずつキーにする**。顔を避けるために独自の道筋 (ハンマーを背中側へ振り込む) を作ったら、参考とまったく違う動きになり、途中で武器も腕も体に隠れた (Glacial Warden)。参考どおりの道筋のまま、手は顔の前ではなく顔より前を通すなど、通り道の細部で顔を避ける。
- **弓は引き絞る動きを見せる**。攻撃の 0.3秒の中で、矢をつがえて引き切った絵を見せてから u = 0.5 で放つ (2章の表の例外)。
- **魔法使いの通常攻撃は、杖を振って唱える動きにする**。手から結晶が飛び出す表現は、何をしているか分かりにくいと言われた (Geomancer)。杖の頭で光がはじける形にした。
- 溜め (`cast`) のループは、始めと終わりで同じ姿勢に戻る周期的な動きにする (2章)。振りかぶった武器は、頭の後ろや顔の前に重ならない向きにする。

### 6.7 描画範囲と検査

- **`frameBox` は向きによって反転しない**。前に伸びる攻撃 (噛みつき・火の玉・矢の雨) は左向きで左へ出るので、左右対称 (`x0 = −x1`) にしておく。羽ばたく翼の振り下ろしなど、足より下に出る動きは `y1` も広げる。
- リグの武器の検査 (`tests/node/lib/clearance.mjs` の `ARMED`) は、持ち手の位置と武器の長さを、絵と同じ数値で書く。右向きでは上半身のひねりで武器の向きの横成分が変わり、柄の後ろの端が胴に入りやすい。突き・振り下ろしでは手を体の外側 (b を大きく) に置き、要所のあいだに中間の姿勢を足して、補間の途中で胴を通らないようにする (Tideling・Coral Knight)。手描きの体に作り替えたら `ARMED` の行を消す (リグの体でしか使えない)。

### 6.8 作業の注意

- **ファイルを書き換えるスクリプトは、スクラッチパッドに Node の .mjs として書いて実行する**。bash のヒアドキュメントに Python や正規表現を直接書くと、バックスラッシュと日本語が壊れる。`sed` の `a\` は行頭の空白を消す。
- `npm run eb:new` の元にするキャラクターの武器の検査が複数行で書かれていると、`ARMED` は自動で足されない (表示される注意に従って手で足す)。
- 手直しは、指摘された1点だけでなく、同じ作りのキャラクター全員に効く原因かを確かめる (弓の放つ時刻は3体まとめて直した。持ち手の入れ替わりは手描きの人型3体を見直した)。
