# 横スクロール化 設計案

4方向 (NW / NE / SW / SE) のアイソメ表示を前提にした Inkstone Character Studio を、左右2方向 (右 R / 左 L) の横スクロール用に改造する計画です。キャラクターは待機・歩行・攻撃の3動作を維持し、8×8ダンジョンは鉛筆画風の横スクロール背景に置き換えます。

## 1. 試作で確かめたこと

共通リグは前ベクトル `f` だけで向きが決まります。右・左の2方向を追加して既存の全キャラクターを描いた結果は次のとおりです (試作ページ `exports/proto/side-angle.html`、Git管理外)。

- **真横 (0°) は不可**: `rf.front` が偽になり、全キャラクターが後頭部の絵になる。頭の描画は正面系・背面系の2種類しかない。
- **真横から20〜30°手前へ向けると成立**: 体はほぼ横向き、顔は手前向き (3/4) になる。全キャラクターが待機・歩行・攻撃とも崩れずに描けた。
- **左右反転を使わないので持ち手は自動で保たれる**: 右向きは剣の腕が手前、左向きは盾の腕が手前。

## 2. 方針

| 項目 | 方針 |
|---|---|
| 左右の描き分け | 反転 (`mirror`) を使わず、リグの投影で左右を別々に描く。既存ガイドの「全体反転で持ち手を入れ替えない」と一致 |
| 視点の角度 | 真横から約25°手前 (`SIDE_VIEW_ANGLE`)。定数1つで調整できる |
| キャラの範囲 | 投影で全キャラクターを一度に左右対応。見た目の調整は戦士から1体ずつ |
| エンジン | `src/` に横スクロール用を追加し、既存ファイルの変更は最小限。`tests/fixtures/src-baseline.json` は意図した更新として再生成 |
| ジャンプ | 初期は入れない。高さ z は持たせて後から足せる形にする |
| 背景の場所 | ダンジョン回廊 → 森 → 城下町 (洞窟は任意) |

## 3. 変更範囲

| 場所 | 変更 |
|---|---|
| `src/characters/rig.js` | `DIRS` に R / L を追加、`SIDE_VIEW_ANGLE`・`SIDE_DIR_ORDER`、歩行速度の換算 `sideWalkSecondsPerPixel` (画面速度 = 4 × 歩幅 × WALK_HZ × cos θ × 倍率 px/秒) |
| `src/rendering/cache.js`・`character-view.js`・`characters/metadata.js` | 4方向固定をやめ、向きの一覧を受け取ってキャッシュ生成・検査 |
| `src/side/` (新規) | 横スクロールのカメラ・ステージデータ・背景レイヤーとチャンク・Renderer・テーマ |
| `src/core/ink.js`・`src/dungeon/stone.js` | そのまま再利用。正面から見た石の描画を追加 |
| `src/dungeon/architecture.js` | `wallFace` を正面の壁にも対応させ、アーチ扉・松明の金具を流用 |
| `studio/` | 向きボタンを右・左、「全方向を見る」を「左右を見る」に |
| `game/` | 8×8ダンジョンを横スクロール確認ページに置き換え (←→ / A D で移動、Spaceで攻撃、背景テーマ選択) |
| 各キャラクター | 向き専用の補正 (`direction==='SW'` など) を R / L に移す |
| `tests/`・`tools/`・`docs/` | 横スクロールの処理のテスト、エクスポート、ガイドの更新 |

## 4. 段階

1. **キャラの左右対応 (エンジン)**: R / L の追加、キャッシュ・カタログの2方向化、Studioの向きボタン。完了の目安は、Studioで全キャラクターが左右 × 3動作で表示されること。8×8ダンジョンは段階5まで従来の4方向で動かす。
2. **キャラ別の調整**: 向き専用の補正の移行、奥側の腕・装備の描画順、横へ伸びる攻撃が `frameBox` を超えないかを `tests/browser/check.html` で確認。戦士から順に。横顔の頭は任意の追加作業。
3. **横スクロールの描画基盤**: カメラ追従、ステージデータ、レイヤーのチャンク焼き込み、描画順、ゲームの移動・攻撃。まず簡易背景で一通り動かす。
4. **鉛筆画の背景テーマ**: ダンジョン回廊を仕上げ、次に森・城下町。
5. **整理**: 旧8×8ダンジョンと4方向UIの退役、ドキュメント・テスト・エクスポートの更新。
6. **(任意) ジャンプ**: 新しい動作 `jump` を各キャラクターに追加。

## 5. 背景の描き方

- **空間**: 奥の壁は真正面の面、床は少し見下ろした帯、手前は縁石の前面と上面。床の奥行き比はキャラの足元の投影 (`KY_G` ≈ 0.4) にそろえ、足が浮かないようにする。
- **4層のパララックス**

  | 層 | スクロール速度 | 内容 |
  |---|---|---|
  | 遠景 | 0.3 | 薄い鉛筆のシルエット |
  | 中景 | 0.6 | 柱の列・窪み |
  | 主役の層 | 1.0 | 壁・床・縁石。キャラが立つ |
  | 前景 | 1.25 | 濃い輪郭とハッチングの柱・鎖。主役を隠さないよう少なめ |

- **鉛筆の濃さで奥行きを出す**: 奥ほど線を細く薄く、点描を少なく、ハッチングの間隔を広くして紙の地を見せる。手前ほど線を太くし、二度描きを増やす。
- **流用する部品**: 揺らぎ線・二度描き・点描・ハッチング・ひび・石の割り付け (`runBlocks`)。松明の炎 `drawFlame` は画面座標の関数なのでそのまま使える。
- **紙の目**: スクロールしない紙の目を最前面に薄く乗算で重ね、スケッチブックの1ページのような統一感を出す (キャラへの影響は実物で判断)。
- **速度と継ぎ目**: 点描は重いので、層ごとに幅512pxのチャンクへ焼き込み、表示範囲だけを保持する。次のチャンクは空き時間に先に作る。乱数の種は部品単位 (`ステージid-層-段-石番号`) にし、チャンク境界をまたぐ石も両側で同じ形にする。
- **テーマの要素**

  | テーマ | 主な要素 |
  |---|---|
  | ダンジョン回廊 | 石積みの壁・アーチの窪みと扉・松明・鎖・石柱・敷石 |
  | 森 | 遠くの木立のシルエット・縦ハッチングの幹・短いストロークの草・点描の土 |
  | 城下町 | 木組みの家並み・窓・石畳・旗 |

- **ステージデータ**: `{ id, theme, length, features: [{ type: 'door', x }, { type: 'torch', x }, { type: 'column', x, layer: 'front' }] }`。地の部分はテーマが自動で敷き詰め、目印だけを手で配置する。

## 6. 決定事項: 上半身のひねり (段階2で導入)

戦士の攻撃で体が薄く見えた原因は、胴・ベルトなどを前後の厚みのない板として描いていることでした。4方向 (45°) では板の幅が約7割見えますが、横向き (25°) では約4割しか見えず、2Dの絵である頭との差で「ぺらぺら」に見えます。攻撃中の上半身のひねりで、さらに真横へ回る瞬間もありました。

比較した案は、A: 上半身だけカメラ側へひねる、B: 胴を立体 (楕円柱) として描く共通部品、C: 横向き専用の2Dの胴、D: 全身を45°にする (足が斜めに滑るので不採用) です。作業量と効果から **A を採用** しました。

- `rigFrame` は横向きのとき上半身 (`U` / `UY`) を `SIDE_CHEST_TURN` = 20° カメラ側へひねる。脚・足 (`W`・`footProj`) は 25° のまま。4方向では `rf.turn = 0` で従来と同じ。
- `bodyLayerKey` はひねりを戻して判定する。
- 戦士: 盾の面を胸と一緒に回す。攻撃のひねりのうちカメラから離れる側を 0.3 倍に弱める。振り下ろしの間だけ剣の向きを進行方向へ戻す。右向きの振りかぶりの位置を胸の座標で調整し直した。
- A で薄さが残るキャラクターが出た場合は、そのキャラクターだけ B を検討する。
- 戦士の調整で分かった横向きの制作のコツ (奥側・手前側の武器、構えの統一、武器が体を通り抜けない軌道と自動検査) は [SIDE_VIEW_GUIDE.md](SIDE_VIEW_GUIDE.md) にまとめた。

## 7. 注意点

- 左右でシルエットが変わる (左向きは盾が手前)。持ち手を保つための意図した結果。
- 顔はやや正面寄りに見える。頭は2Dの絵として描いているため。完全な横顔にはキャラごとに頭の新規作画が必要。
- 背景の区画の焼き込み時間は、段階3の仮の背景で1区画あたり約1〜2ms (DPR 1)。点描の多い段階4のテーマでは増えるので、改めて計測する。

## 8. 段階3の結果: 横スクロールの確認画面

- `scroll/index.html` (メニューの「横スクロール」、Studio の詳細画面の「横スクロールで見る」)。← → (A / D) またはボタンを押している間歩き、Spaceで攻撃する。8×8ダンジョンは残している。
- 描画は `src/side/` (`createSideRenderer`)。カメラは画面中央の遊びの外で追従し、ステージの端で止まる。背景は層を512論理pxの区画に焼き込んで使い回し、遠景 0.3・中景 0.6・主役の層 1 の速さで流れる。段階4ではテーマ (`src/side/themes/`) を追加するだけで背景を差し替えられる。
- ゲームの動きは `scroll/game.js`。歩行の時間は横に歩いた距離から決め (`sideWalkSecondsPerPixel`)、足が滑らない。攻撃中は移動せず、終わったときに押し続けていれば歩き出す。弓を持つキャラクターは `releaseAt` の位相で矢を1本放ち、矢は向きの側へ画面の水平に飛んで、一定の距離で消える。
- 確認: `tests/node/scroll.test.mjs` (ステージ・カメラ・背景の区画の範囲・歩行・端・攻撃・矢・入力)。ブラウザーで全11体 × Live / Cached の歩行・向き変え・攻撃にエラーがないこと、矢が引き手から飛ぶことを確認した。
